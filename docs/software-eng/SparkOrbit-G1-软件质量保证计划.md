## 4 标准、条例和约定

### 4.1 编码标准

| 维度 | 标准 |
|------|------|
| 后端语言 | Python 3.12+，遵循 PEP 8 |
| 前端语言 | TypeScript 5.x，遵循 ESLint 推荐规则 |
| 代码格式化 | Black（Python）、Prettier（TS/Vue） |
| 提交信息 | `type(scope): message` 格式（见 G2 §2.2） |

### 4.2 文档标准

| 维度 | 标准 |
|------|------|
| 源码格式 | Markdown（UTF-8，Git 可 diff） |
| 交付格式 | Word（.docx，含嵌入截图与渲染图表） |
| 命名约定 | `SparkOrbit-XX-中文名.docx`（XX 为 A1–G2） |
| 版本标识 | VX.Y（X=主版本 Y=修订），每份文档独立版本号 |

### 4.3 测试标准

| 维度 | 标准 |
|------|------|
| 单元测试 | 核心服务模块覆盖率 ≥70% |
| 功能测试 | 十一大测试族 54 用例，通过率 100% |
| 冒烟测试 | Docker Compose 一键启动成功 + 三角色登录可用 |
| 回归测试 | 每次功能合入 main 后全量跑 |

## 5 评审与检查

### 5.1 评审节点

| 阶段 | 评审内容 | 输入 | 输出 |
|------|----------|------|------|
| 需求评审 | B1/B2 完整性 | 需求说明书 | 评审记录 |
| 设计评审 | C1/C2/C3 一致性 | 设计说明书 | 评审记录 |
| 代码评审 | 核心模块正确性 | 源程序 | 评审记录 |
| 面试/求职模块评审 | 三模式编排/多模态评分/投递看板正确性 | interview_agents.py / interview_scoring.py / interview_applications.py | 评审记录 |
| 测试评审 | E1/E2 覆盖率 | 测试文档 | 评审记录 |
| 提交评审 | 全部交付物 | 竞赛提交包 | 验收结论 |

### 5.2 检查项

| 检查项 | 方法 | 标准 |
|--------|------|------|
| 文档版本一致性 | 交叉引用验证 | 无断裂引用 |
| 截图槽位完整性 | 逐文档对照 H7 清单 | 100% |
| 代码可构建 | Docker Compose 冒烟 | 一键启动成功 |
| 核心功能可用 | 11 族冒烟 | 全通 |
| 文档体积差异 | 各册 Word 不小于 50KB | 无空壳导出 |

## 6 工具、技术和方法

| 工具 | 用途 |
|------|------|
| Git | 版本控制（分支策略见 G2 §2.2） |
| GitHub | 代码托管 + Issue 跟踪 |
| Docker | 环境一致性（四服务编排：MySQL + Backend + Frontend + Codelab-Runner） |
| pytest | 后端单元测试（`pip install -r requirements-dev.txt`） |
| python-docx | Markdown → Word 批量导出 |
| Markdown | 文档编写（Git 可 diff） |

## 7 媒体控制

| 媒体类型 | 存储位置 | 备份策略 |
|----------|----------|----------|
| 源代码 | GitHub 仓库（私有） | 本地硬盘 + GitHub 远端 |
| 数据库种子 | `backend/seed/` | 随源码包打包 |
| 知识库（ChromaDB） | `backend/data/` | 随安装包提供 |
| 截图证据 | `docs/evidence/screenshots/` | 逐份文档内嵌 + 独立目录备份 |
| 演示视频 | 本地 MP4 + 网盘 | 加密链接提交组委会 |
| PPT | 本地 PPTX + 网盘 | 与视频同步提交 |

## 8 对供货单位的控制

本项目无外部供货单位。所用第三方服务（DeepSeek API、讯飞 API、火山方舟 Seedance）通过 API Key 鉴权，费用独立核算，不涉及代码或文档交付。
