## 3 开发工作评价

### 3.1 技术方法评价

| 技术点 | 评价 | 说明 |
|--------|------|------|
| LangGraph 多智能体 + SSE 流式 | 优秀 | Coordinator 编排 + 流式推送，用户感知好；国赛闭环核心卖点 |
| FastAPI + SQLAlchemy 2.0 异步 | 优秀 | 高性能、自动 OpenAPI 文档，降低前后端联动摩擦 |
| Vue 3 + Three.js + GSAP | 优秀 | 3D 星轨领航台与动画效果达到竞赛级视觉水平 |
| Docker Compose 一键部署 | 优秀 | 评委侧零环境摩擦，国赛提交即沿用此模式 |
| ChromaDB + RAG | 良好 | 辅导回答与资源生成的教材溯源有效；384 维模型精度可提升 |
| Shield 幻觉防控三级防线 | 良好 | 多模型交叉验证实现，但增加了 API 成本与延迟 |
| TensorFlow.js 本地推理 | 良好 | 自习督导隐私友好，COCO-SSD 精度对使用场景足够 |
| 面试三模式编排（workflow/handoff/council） | 优秀 | 准备真并行 + 单轮 LangGraph astream + 总评 asyncio.gather，均写 agent_steps 可回放 |
| 多模态面试评分 | 良好 | 语义 70% + 韵律 15% + 仪态 15% 融合，缺失模态自动降级 |

### 3.2 质量评价

## 4 经验与教训

### 4.1 主要经验

1. **高强度 AI 辅助冲刺可行**：国赛闭环约 5 天内从零搭通全部 2.2.1–2.2.5 功能 + 前端视觉，挑战赛增量两天内落地 5+ 个主力新模块，说明 AI 协同开发效率极高
2. **画像驱动闭环是有效范式**：采集→路径→评估→重排形成自反馈，在国赛评审中获得认可
3. **Docker 一键部署降低评审摩擦**：评委无需安装 Python/Node/MySQL，docker compose up 即可
4. **国赛证据前置打包有效**：evidence 目录提前归档，国赛提交无需事后补拍

### 4.2 主要教训

1. **国标文档启动过晚**：16 份文档集中在 07-31 一天内从上轮对话产出，压力极大；应在冲刺期同步分周写，而非功能完结后才集中赶
2. **挑战赛三周计划压缩至两天**：v4/v5 计划排了三周（W1–W3），因前有空窗，实际在 07-29 才重启，导致部分演示证据和交互细节的完善度不足
3. **演示视频与 PPT 仍待固化**：截至 07-31，H5 演示视频尚未实际录制（仅有脚本），H6 PPT 未定稿（仅有脚本），这是最紧急的提交缺口
4. **截图与证据未随功能同步归档**：部分截图槽位（如评估报告 eval_report_02/03、资源溯源、代码舱运行结果等）在功能构建时未随手截取，事后补拍成本高
5. **计划与实际偏差距大时未及时修订进度文档**：本报告 V1.0 中的进度对比表按照理想化甘特图回填，与真实开发节奏不符
